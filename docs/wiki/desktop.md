Milim is your local control plane for coding agents: use your own models and subscriptions, keep one canonical thread, review the diff, and ship.

Account-runtime cards compare the installed CLI with its latest stable release, highlight available updates, disable the action when current, and keep it neutral if the release check is unavailable.

The Providers sheet uses branded icons for saved providers, setup shortcuts, detected local runtimes, and the separate Codex, OpenCode, Claude, and Pi account-runtime cards. Pi reports its configured provider and model counts with refresh and `/login` guidance. Cards use a two-column grid: four runtimes render 2×2, while a final odd card spans both columns.

Git-backed New Chat flows use the configured workspace preference. The split-button menu can explicitly start in the current checkout or an isolated worktree. Isolated threads execute from `~/.milim/runtime/threads/<thread-id>` on a retained `milim/thread-<short-id>` branch while continuing to group under the original project. Uncommitted changes in the original checkout are excluded. Archive preserves the worktree; deletion removes a clean worktree or asks before force-discarding dirty state, and never deletes its branch.

The Code inspector is a workspace-first mini editor with one persistent, collapsible, pointer- and keyboard-resizable file rail. Folders expand inline and quick search scans recursively while `.git`, dependency, build, and generated directories stay hidden. One workspace file can be edited at a time; generated artifacts remain in a secondary group labelled read-only. The Git inspector opens the current branch PR in its in-app cockpit or creates a GitHub draft after commit and publish prerequisites are met. Ready DOM previews expose an annotation crosshair that captures bounded element metadata without screenshots or complete DOM persistence.

Resizable pane boundaries use one 12px pointer target centered on the visible seam, with the same quiet grip, focus state, and active state in the Sidebar, Inspector, Code and Git rails, Pull requests, Media Studio, and Preview logs. A layout with an intentional gap centers that same target in the gap rather than offsetting it into either pane.

Milim has one model-agnostic workbench. Project, Agent, MCP, media, memory, sandbox, schedule, and computer-use features are always discoverable, with advanced tools collapsed until needed. The sidebar Tools launcher opens MCP servers, Skills, Schedules, Pull requests, and the media manager from one persistent place. The Tauri process starts the embedded backend, connects persisted MCP servers, and runs schedules in the background. The model picker emits cached provider rows immediately, then merges the provider refresh and each Codex, Claude, OpenCode, or Pi discovery lane independently. A slow CLI cannot block usable provider models, and a failed lane does not clear existing rows. Background schedule completions and mobile control events use shared app notices so they remain visible outside their settings panels. Closing the desktop window hides it to the system tray so server-owned runs, queues, approvals, and schedules keep running; use the tray menu to reopen or quit. Launching Milim again restores and focuses that existing window instead of starting another app instance. Explicit Quit and restart cancel canonical runs and close Milim-owned MCP, agent-runtime, host-shell, sandbox, and preview process trees. Programs deliberately opened in a browser or editor, plus the updater handoff, remain detached so they can outlive the app.

Thread messages, reciprocal links, mailbox exchanges, accepted runs, queued turns, and approval lifecycle are authoritative in Rust and SQLite. The React session store is a presentation replica plus client-local pane, selection, and draft state. Creating a chat provisions its chosen ID through canonical `thread.create` before activating the local replica, but an empty chat stays out of desktop thread navigation until its first message is sent. An ambiguous transport failure retries once with the same command ID, while a rejected create leaves the current chat unchanged. Renderer reload hydrates a bounded timeline tail and active run snapshot, then fills sequence gaps; it neither resumes nor duplicates execution. Each accepted run freezes its effective model, app-wide and thread instructions, workspace, privacy, Review and plan state, Agent, tools, skills, attachments, native session identity, and the revision and maximum visible sequence of each available linked chat.

## Interface modes

| Mode | Visible surface |
|---|---|
| Unified workbench | Chat plus workspace/Git, Agents, skills, MCP, schedules with attached file context and visible result threads, media, sandbox, computer use, and Personal/Project memory. |

Thread export reads one complete SQLite snapshot after pending renderer writes are flushed, so JSON and Markdown exports include older messages that have not been loaded into the window. Branching clones canonical history on the desktop before exposing the new chat. Branch-at-message uses the selected message's stable identity, includes the full history through that message, and gives copied messages new identities; retry branches resolve their starting point against the same complete history. A branch that finishes after you navigate elsewhere does not switch you away from your current chat.

Unsent text and attachments are saved together per thread, including attachment-only drafts. Switching chats preserves both, and a file read finishing after navigation adds to its original chat. Queue and steer acknowledgments clear only the submitted text and attachment identities, preserving anything you typed or attached while waiting. IME composition-confirmation keys do not submit the composer or accept an autocomplete suggestion.

Settings > Models includes optional provider run limits: model steps, elapsed seconds, and a USD spend threshold. New desktop and mobile provider turns freeze these limits when accepted; changing settings does not affect a running turn. Without overrides, the existing 100-step cap remains and time/spend are unlimited. Codex, Claude, OpenCode, and Pi retain their own execution controls.

Time and spend are checked at model/tool boundaries, including after approvals. Started requests and tools finish safely, so these are soft bounds rather than prepaid billing caps. Spend uses provider-reported cost or cached per-token pricing; unavailable cost pauses further work instead of counting it as free. A limited run retains its transcript and leaves queued prompts pending. Send **Continue** for another bounded run, or use **Run** on a queued prompt. Branches share their selected folder without acquiring ownership of a source chat's managed worktree.

## Context menus

The desktop app replaces the default right-click menu on Milim-owned surfaces with app actions for threads, project sections, chat messages, artifacts, preview panels, Git panels, and empty app chrome. Text inputs, textareas, selected text, and links keep the native browser menu for edit, copy, paste, select-all, and link actions. External pages inside the native preview child webview keep their own native context menu; the Milim preview toolbar and panel chrome use the app menu.

The Milim logo in the existing title bar opens a compact app menu for new chat, composer focus, settings, documentation, diagnostics, and a flush-safe quit; sidebar visibility appears only in Sidebar placement. It supports first-item focus, arrow/Home/End navigation, Escape dismissal, and configured shortcut labels without adding a second title-bar row. On macOS, the system menu bar also exposes native Milim, File, Edit, View, Window, and Help menus; standard text editing stays native while custom actions route into the same desktop commands, and the View sidebar item is disabled while a horizontal rail is selected.

User and assistant message bodies render Markdown in the transcript, and message bodies plus the composer use automatic text direction so Hebrew and other RTL text read naturally. Completed assistant HTTP(S) links render as compact source chips whose hover or keyboard-focus detail shows the label, host, and path without fetching remote metadata; activating one still uses the system browser. As soon as a turn is accepted, the transcript tail shows a transient shimmering `thinking...` cue; the first assistant activity replaces it, and the cue is never stored as a blank message. While an assistant response is still streaming, adjacent account-runtime answer fragments are combined into one live answer block, memoized Markdown keeps expensive final-pass features disabled regardless of response length, and its loading fallback collapses token newlines instead of presenting one token per line. The answer switches to full Markdown when the turn finalizes without remounting the canonical run's assistant row. Auto-follow remains coupled only near the bottom and follows descendant height changes from Markdown, images, diagrams, charts, Apps, and Worker activity. Scrolling upward freezes the visible row and reveals a keyboard-accessible **Latest** control; background output does not reattach the reader, and selecting **Latest** returns to the newest output. Long transcripts virtualize offscreen rows while preserving an overlapping visible-row anchor as their mounted window moves. Message actions, edit/resend, search, model context, and thread export keep using the raw stored source.

The composer keeps prompt storage plain text. Recognized `@Skill Name`, `/Skill Name`, and `/server__tool` tags render as compact pills, while workspace `@file` references and bare HTTP(S) URLs render with link-like highlighting. Pasting a standalone HTTP(S) URL inserts a trailing space so following text stays outside it. GitHub URLs become atomic inline links with the GitHub icon and a shortened path, while sending and copying preserve the full URL shown in the hover tooltip. Ctrl/Cmd-click opens the system browser, while Ctrl/Cmd-Shift-click opens a new sidepanel browser tab. MCP slash suggestions insert the visible tag only and do not force a tool call or bypass approval/exposure policy.

Automatic and Custom skill modes rank at most three enabled candidates per turn. Ordinary turns include only compact names and descriptions, then expose read-only `milim_skill_search` and `milim_skill_read` tools so a model can load a complete skill only when it chooses to use it. Custom mode restricts both selection and lazy reads to the Agent's allowlist. Explicit `@Skill Name` or `/Skill Name` references load that enabled skill immediately. Whole skill bodies are either retained or omitted at the prompt budget boundary, never cut mid-instruction. Account runtimes keep their own native skill discovery and receive Milim-managed skills through the same per-turn gateway without duplicate eager bodies.

PNG, JPEG, WebP, and GIF attachments up to 2 MB each are preserved as real image content for provider chat, server-side agent runs, Codex app-server, Claude CLI, Pi RPC, and provider-backed schedules. Browser and native attachment paths use the same validation and reject unsupported binary types plus oversized, empty, or unreadable images before attaching them. Text files may be larger than 2 MB because Milim records their original size while sending only a bounded 128 KiB preview marked as truncated. A selected model that explicitly reports `imageInput: false` rejects images from paste, drop, picker, workspace attachment, queue, steer, retry, and send paths with a composer-level recovery notice; if an image was drafted before switching models, send stays disabled until the image is removed or a vision model is selected. Missing capability metadata remains unknown and permissive. Each outbound turn keeps the latest images and then complete recent image-bearing turns newest-first within a 20 MiB encoded-image budget. Older pixels stay visible in the local transcript but are replaced by an omission note in model context; a final 30 MiB desktop body check reports removal/compaction guidance before the embedded server can return 413. Codex receives temporary `localImage` inputs; Claude and Pi receive native base64 image blocks; none of these paths uses OCR. Desktop files come from the native picker, clipboard, a file drop anywhere in the Milim window, or workspace-relative `@file` suggestions under the selected folder. Only external file payloads activate the full-window **Attach to** affordance; ordinary text/URL drags are ignored, and the same conversion, validation, notices, and 12-item attachment limit are reused exactly once. Tauri native drag/drop remains disabled so WebView HTML file drops keep ownership. Screenshot pastes collapse `files`/`items` twins and PNG/BMP clipboard copies into one attachment.

## Linked chats and mailbox

Links are durable, reciprocal, and may cross projects. Linking chat A to chat B grants each chat access to the other, shows a pill in both composers, and does not merge either transcript. Unlinking from either composer removes both grants. Existing one-way links are made reciprocal during migration. At run acceptance Milim freezes each available target's identity, title, project/workspace, model/runtime, thread revision, epoch, and maximum timeline sequence. The fixed prompt receives only lightweight metadata; full transcript content is available on demand through `linked_thread_read`, which returns canonical visible user/assistant content and attachment metadata only. Hidden prompts, reasoning, tool ledgers, and account-runtime internals are excluded. Reads default to 20 messages, allow at most 50, cannot pass the frozen sequence, and cap a result at 64 KiB.

`linked_thread_list` and `linked_thread_read` are read-only and parallel-safe. `linked_thread_send` is mutating and exclusive: Plan and Guarded do not expose it, Review asks for an exact approval, and Open can send immediately. `linked_thread_wait` is available alongside send without a second approval. A Custom Agent must allow each tool it needs. A send starts the destination with its own model, Agent, workspace, privacy, and approval settings when idle. When the destination is busy, the message steers its active run if that runtime supports steering; otherwise it joins the durable follow-up queue. A steer that misses the active run's next model step is preserved as a queued follow-up. Automatic mailbox delivery never interrupts active work. The target sees a provenance-marked **From** message, and unlinking later does not revoke a grant already frozen into an accepted run.

Completion or terminal failure produces a mailbox reply in the origin transcript without starting or waking an origin run. When the current run depends on that result, it can pass the send's exchange ID to `linked_thread_wait`; the default wait is 60 seconds, each call is capped at 90 seconds, and a timeout can be repeated without consuming or discarding the eventual reply. A successful wait atomically consumes the reply into that requesting run so it is not injected again later. Waits are restricted to exchanges created by the same run and a target in its frozen grants, and cancellation simply drops the wait while leaving mailbox state durable. Otherwise the origin's next actually started turn claims pending receipts as bounded system context, including durable queued turns and native account-runtime sessions, and records the claimed mailbox IDs in run inspection. Accepted runs retain their frozen grant after an unlink. Restart reconciliation preserves queued mail and converts interrupted target work to a failure receipt. Deleting the origin leaves the target transcript intact and discards undeliverable return mail. There are no linked-chat stop or open-dialogue tools.

## Desktop performance and history loading

Startup reads a session manifest containing thread metadata, message counts, previews, and loaded ranges. It hydrates only the latest 100 messages for the active and canonically busy threads; older messages load in 100-message cursor pages while preserving the visible scroll anchor. Hydration and persistence keep stable message IDs unique; SQLite absorbs a stale renderer projection when an authoritative terminal reply already exists and rejects other duplicate IDs. Search uses local SQLite FTS with role and archive filters and returns at most 20 ranked matches, so unopened message bodies do not need to enter the renderer. Incremental session operations update metadata and changed message rows without rewriting unloaded history or transient streamed text.

The transcript keeps at most 200 rows mounted and moves that window in 100-row increments. Per-thread row measurements and gap-aware spacers estimate unmounted height; every window move restores an overlapping visible row before paint. Completed Markdown blocks remain memoized while only the mutable streaming tail is reparsed; syntax highlighting waits for completed output. Inspector, Git, Workers, Preview, settings, media, and pull-request JavaScript and CSS load only when their surfaces open. Hidden windows stop canonical polling, preview probes, quota refreshes, and Git/PR subprocess work; canonical active-thread updates normally arrive through one resumable WebSocket with slow polling only as reconnect fallback.

Run inspection remains byte-for-byte lossless while using a content-addressed SQLite blob store. JSON artifacts larger than 1 KiB use zstd level 3 when beneficial. Provider requests use verified prefix/suffix deltas from the prior request and a full checkpoint every 25 model steps. A two-connection WAL read pool handles bootstrap, paging, search, timeline, and inspection reads while one ordered writer remains authoritative. Legacy artifact and FTS migration runs off the async worker pool in bounded idle batches and pauses while a run is active.

`pnpm -C apps/desktop perf:canonical` builds a release-optimized, non-bundled Tauri binary with the test-only `perf-diagnostics` feature and runs the canonical reload/queue continuity benchmark against a private deterministic fixture. Perf processes bypass normal single-instance forwarding so a running development or installed Milim window cannot absorb a sample; production builds retain the single-instance behavior. Its `PerformanceReportV2` records native startup stages, SQLite lock and transaction metrics, timeline and artifact I/O, subprocess launches, renderer renders/long tasks/frames/DOM/heap, process memory, initial bundle sizes, and a commit, dirty-diff, machine, OS, WebView, build-profile, and fixture fingerprint. The dev benchmark remains a smoke check and is not a release baseline.

`pnpm -C apps/desktop perf:suite` runs that canonical scenario in seven fresh release processes and writes median/p95 samples to `canonical-suite/performance-suite-v2.json`; add `--enforce` through the `perf:suite:enforce` script only on a pinned benchmark machine. The suite report labels its current scope explicitly: the scale, ten-minute idle, migration/compaction, backup/restore, compositor-theme, and macOS parity scenarios are not promoted by the canonical runner yet.

Schedules accept the same stored `dataUrl` pixels and build a multimodal user message when they fire. New schedules start with the active thread's workspace and privacy mode, evaluate cron in local time by default, and expose editable workspace, Privacy, and local/UTC choices plus the server-computed next run. Existing schedules migrate explicitly to Privacy Off and UTC. Every scheduled occurrence uses Guarded approval, creates a canonical thread marked with its schedule origin, and replicates to desktop and mobile like any other run; retries reuse deterministic command receipts instead of creating duplicate work. Invalid attachments and rejected turns record a visible failure in that occurrence instead of reporting success. A legacy scheduled image without stored pixel data records a visible reattachment error in that thread. Background schedules list and accept provider/local API models only; account runtimes remain interactive because their approval and session semantics are not safe for unattended runs.

## Session controls

Hot Swap makes the Milim thread canonical rather than any provider session. Selecting a compatible chat model changes the next turn immediately without resetting workspace, memory, artifacts, previews, approvals, goals, or queued messages. A preflight appears only when the target needs context compaction, cannot receive current image/tool context, is unavailable, or has a native Codex/Claude session behind the Milim transcript.

For a stale native session, **Fresh** starts from Milim's complete context while **Resume** keeps the native session and injects turns added since it last completed successfully. The latest completed assistant response permanently exposes a labeled, keyboard-focusable **Continue with…** action; **Review with…** and **Retry with…** remain in its adjacent menu. Continue and Review prepare editable drafts; Review is read-only for that turn only. Coding retries run from the pre-turn checkpoint in an isolated Git worktree and expose their diff in the Git inspector before it can be applied to the original workspace.

The Codex and installed Claude CLI account cards include **Import chats**. Both open searchable project-grouped pickers for selecting whole projects, the no-project group, or individual chats; existing imports are excluded and expose **Open** instead. Codex defaults to an All scope that includes active and archived app-server history, with narrower Active and Archived controls. Project selection always covers every not-yet-imported chat in the current scope even while search filters the visible rows. Imports run sequentially, continue past individual failures, and keep results available for review or retry.

Claude reads locally retained top-level project transcripts and imports the active branch's human/assistant text while omitting reasoning, tools, task notifications, attachments, and internal scaffolding; media-only prompts are marked as omitted. An available project folder attaches the original native session and sync cursor. Missing folders stay grouped under their recorded path but never become a Milim workspace; missing Claude projects import as transcript-only and force the existing Fresh/Resume choice before continuation. Imports are one-time and never continuously merge native history.

The Git inspector is a review-first workspace with a compact repository header for branch, status, fetch, commit, sync, and agent review actions. Its edge-to-edge body places a folder-structured changed-file navigator on the left and the local unified diff on the right. The scope selector immediately switches between all changes, unstaged changes, staged changes, the latest turn checkpoint, a recent commit, or another local branch without contacting GitHub. Selecting a file loads the current scope when needed, expands its section, and scrolls it into view; the toolbar can expand or collapse every rendered section, show or hide the navigator, the divider resizes it, and narrow panels stack it above the diff.

When the current branch has a GitHub PR, the Git inspector adds a **PR #N** view beside Changes. It shows branch/base and line totals, requested and completed reviews, checks, Markdown descriptions and comments, and a derived merge-readiness state. GitHub-authored HTML is parsed only in this PR surface and sanitized before rendering, so subscript notes, linked badges, and bounded attachment images remain visible while scripts and unsafe attributes are removed. From this view users can add a comment, approve/request changes, mark a draft ready, or merge after choosing merge/squash/rebase; Merge is enabled only when the authenticated GitHub user has write, maintain, or admin repository permission, and sends the displayed head SHA so a changed PR cannot be merged accidentally. **Prepare to merge** drafts an editable agent prompt to review and fix actionable blockers but never sends or merges automatically. Merged and closed PRs are read-only. Inline GitHub review threads, check logs, label/reviewer/title editing, close/reopen, auto-merge, admin bypass, and branch deletion remain on GitHub.

The **Pull requests** tool searches the authenticated GitHub account for open PRs authored by the user or requesting their review. Its persisted resizable workspace filters and searches that list on the left, with a persisted draggable divider between the list and Summary, Timeline, or Code details. GitHub user and App avatars plus saved list/detail data render immediately while background refreshes upsert current data. A failed first load distinguishes a missing GitHub CLI, missing `gh` authentication, network failure, or another CLI error; the recovery state keeps Retry, links to the relevant setup help when available, and puts raw output under Technical details. Comments, reviews, draft readiness, and explicit merge/squash/rebase actions use the same validation and displayed-head guard as the Git inspector.

Sidebar PR badges refresh on startup, focus, mutations, and every minute while an open PR is visible. Background reads are scoped to each isolated worktree without changing the active workspace; the active shared checkout also participates, while inactive shared-checkout chats are intentionally unbadged because they do not own a stable branch. Activity and unread indicators take priority over PR state. A failed refresh keeps the last known PR visible as stale and retries later. These features require a GitHub origin plus the separately installed and authenticated `gh` CLI.

The latest eligible turn ends with a compact review card whose explicit state is checking, ready, no changes, or unavailable. In ready state, **Review changes** opens the resulting checkpoint diff in the Git inspector, while **Undo** restores the checkpoint, removes that assistant response, retains the user request, and clears stale account-runtime state. Unavailable review keeps **Retry** and **Open Git** visible instead of removing recovery actions.

## Artifacts

Named artifacts from later assistant messages become selectable revisions of the same logical file or title. Revisions are immutable snapshots from chat history; preview, copy, download, diff review, apply, and save actions use the selected revision. Threads without a selected folder save/apply named artifacts into a persisted per-thread virtual project; threads with a folder write to disk. Extracted code artifacts collapse to compact source rows in the transcript; open the side panel or review a workspace diff to inspect the full source. Inline artifacts, including anonymous code fences, markdown tables, standalone JSON, and standalone CSV, remain display/export content and do not get workspace target paths, batch apply, or save controls. Saved files record the source app session, message turn, and artifact revision when available.

## Mermaid diagrams

Completed fenced `mermaid` blocks in user and assistant transcript messages render as responsive diagrams without changing agent prompts or requiring a tool call. An unfinished streamed fence remains ordinary code until its closing fence arrives. Diagram and Code tabs keep the original Mermaid source available, while actions copy the source or a PNG image and download standalone SVG or 2x PNG files. PNG output uses the active card background, preserves aspect ratio, and caps either dimension at 4096 pixels.

Mermaid loads only when a diagram is present and uses strict security with bounded source and edge counts. HTML labels and click handlers remain unavailable. Anonymous Mermaid fences do not create duplicate artifact cards; an explicitly named Mermaid file continues through the normal generated-file workflow.

## Native charts

The built-in read-only `render_chart` tool accepts bounded structured data for bar, line, pie, and scatter charts. Bar charts may set `orientation` to `vertical` or `horizontal`; omitted orientation remains vertical, and horizontal bars place category labels on the left and values along the bottom. Optional `x_format` and `y_format` metadata provide locale-aware number, percentage-point, and currency formatting with bounded precision, compact notation, and explicit positive signs. Milim renders the result as a responsive native SVG at the exact tool-call position, persists its validated chart specification with the transcript, and exposes the same formatted data through an accessible table.

Hover or focus a mark to inspect it; tapping pins its pointed tooltip until another mark or the surrounding chart is selected, and the matching category label gains emphasis. Bar and line tooltips compare every visible series at the active category, while pie and scatter tooltips remain mark-specific. Keyboard arrows follow the visual direction: left and right move within vertical-bar, line, and scatter series, while up and down move within horizontal-bar series; the other arrow pair changes series at the same category. Legend buttons show or hide series or slices, and line and scatter charts add a crosshair to the active point. Layout, tick density, direct bar labels, and label wrapping adapt to the transcript width. Bars stay square at zero, round only at the value end, use a restrained accent-derived gradient without encoding another value, and reveal outward from the baseline with a short stagger. The renderer honors reduced motion and does not require an installed MCP server, remote HTML, or network access.

## MCP Apps

Provider/local chats and Codex, Claude, OpenCode, and Pi account runtimes can manage the same MCP server registry as the MCP Servers sheet through `mcp_server_list`, `mcp_server_test`, `mcp_server_save`, and `mcp_server_delete`. Chat setup accepts ordinary environment values separately from value-free secret placeholders. Credential-looking keys cannot carry values through model tool arguments; add those values afterward in the MCP Servers sheet, where the existing encrypted secret store handles them. A successful connection updates the shared hub immediately, and its advertised tools appear when the next chat turn captures a fresh tool registry.

MCP Apps are server-authored live views, not artifacts. When a connected stdio MCP server and Milim both negotiate `io.modelcontextprotocol/ui`, a tool may attach an advertised `ui://` resource. Milim inserts that chart, diagram, form, dashboard, or viewer at the exact tool-call position and keeps it out of completed-tool groups and the artifact panel.

Each view runs inline in a dedicated opaque-origin iframe with scripts and forms but no same-origin, navigation, popup, download, or device privileges. Milim persists the view descriptor and initial tool result, but never persists the remote HTML. Reopening a thread re-reads the resource from its MCP server. If the server is disconnected or the resource fails URI, MIME, CSP, or size validation, the normal textual result remains visible with a retry state. The first release is desktop-inline only for Milim-managed stdio servers in provider/local-model agent runs; mobile and native Codex/Claude events keep text fallback.

## Workspace checkpoints

Tool-enabled turns with a selected Git workspace create a Git worktree checkpoint before the assistant can write files or run commands. Assistant messages with a checkpoint expose a restore action that returns the workspace files to their pre-turn content without moving the current branch HEAD.

## Git side panel

The Git side panel appears only for selected folders that are Git repositories. Its branch selector lists local branches, can checkout another local branch, and can create a new branch from the current `HEAD`; checkout failures are reported from Git without changing the worktree.

## Plan mode

Plan mode injects a system instruction that allows read-only inspection and blocks edits, writes, shell commands, computer control, schedule creation, memory registration, and other mutations. The assistant returns a concrete implementation plan. The UI exposes an Execute plan action that sends the approved plan back as a normal run.

## Goals

Goals are thread-level autonomous runs, not saved agent profiles. A goal stores objective, success criteria, constraints, status, last reason, next prompt, turn count, timestamps, and an optional developer max-turn cap. After each visible turn, a controller asks the model whether to continue, complete, or stop as blocked.

The chat transcript upserts each tool lifecycle by call id, keeps readable approval outcomes instead of protocol option payloads, and preserves visually shortened command text exactly in its tooltip and copy action. Git and preview review comments remain editable in the composer tray and are sent as bounded structured context with the next user turn to provider models and all account runtimes. After every successful Google Sheets, Docs, or Slides edit tool finishes, Milim immediately refreshes the open native preview, including edits made through account runtimes such as OpenCode.

The Context panel's explicit **Inspect effective run** action is a dry run of configuration resolution. It uses the current draft and attachments and shows the privacy-processed prompt layers, runtime boundary, model, workspace, approval/privacy/memory/delegation policy, Agent tool and skill selection, attachment digests, and the source thread revision. It never sends the prompt, creates a run, or claims pending inbox inputs.

While a Milim provider-agent run advertises steering, Ctrl/Cmd+Enter and the expanded busy composer's secondary menu send the current composer input as **Steer next step**. Active run identity and steering capability follow the canonical run snapshot reactively, so background synchronization cannot silently disable the shortcut. The primary busy Send action remains Queue. Steering is a durable ordered input for the next Milim-owned model boundary and immediately appears as a separate **Steer · Pending** user bubble in the running transcript. Claiming it removes the pending state without replacing the original prompt, and reconnecting clients restore its bounded display text and attachments from canonical state. Unsupported native account runtimes keep modifier-Enter as queue submission and never substitute cancellation for steering. Injected context has no permanent composer control and does not wake an idle run.

## Slash commands

| Command | Behavior |
|---|---|
| `/plan build feature X` | Turn on read-only planning and send the remaining text as the prompt. Selecting `/plan` from autocomplete activates its pill immediately and leaves the composer ready for the prompt. |
| `/goal build feature X` | Start a goal with the remaining text as its objective. Selecting `/goal` from autocomplete activates a removable Goal pill, and the next prompt becomes the objective. |
| `/model llama3.2` | Set the thread model. |
| `/folder C:\project` | Set the thread working folder. |
| `/sandbox` and `/nosandbox` | Enable or disable sandbox tools. |
| `/computer` and `/nocomputer` | Enable or disable computer-use tools. |
| `/memory` and `/nomemory` | Enable or disable scoped memory. |
| `/privacy redact` | Set the outbound privacy gate to `off`, `redact`, or `block`. |
| `/approval guarded` | Set tool approval to `review`, `guarded`, or `open`. |

Calling `/privacy` or `/approval` without one of those valid arguments shows usage help and leaves the current state unchanged.
| `/agent none` | Switch to a named agent by id/name, or clear the active agent. |
| `/compact` | Summarize prior context into a visible checkpoint and start future model calls from that summary. |
| `/export` | Download the active thread using the configured JSON/Markdown default. `/export json` and `/export md` override it. |
| `/import` | Pick a Milim JSON or Markdown thread export and import it as a new local thread. |
| `/clear` | Start a fresh chat through the shared inherited/configured new-chat policy. Computer Use, Plan Mode, goals, temporary instructions, and running state always reset. |
